#### 汇总

- 稳态每 1 s ≈ **35 次系统调用**（3 open / 3 close / 4 stat / 13 read / 10 lseek / 2 write），≈ **300 万次/天**；无 fork。
- 每 5 s 额外 ≈ 10–12 次系统调用 → 折合 ≈ 2.4 次/秒。
- 每 60 s 额外：zone 重扫 ≤64 `open`+64 `read`+64 `close`+20 次 fd 重开；`/proc` 看门狗（仅 `APP_LAUNCH_ENABLED=1` 时）一次全目录扫描。
- **fork 不在稳态节拍里**，只在「本轮实际下发」时出现：`RAMP_DISPATCH=1`（默认）下每个变化周期 **5 次 `am` 广播**（5 s 内每秒 1 次），关闭时为 1 次。

### A2 休眠/待机时 daemon 与模块各自在做什么

- **daemon**：无 `WakeLock`、无 `AlarmManager`（全仓 `grep WakeLock/AlarmManager` 为空），`sleep(1)` 不能唤醒整机 → **整机 suspend 期间不运行**，内核定时器不执行；但只要 CPU 被其它事件唤醒（蓝牙收包等），1 s 拍立刻继续。断联时 `append_webui_row()` 直接返回（`:5059`），不写曲线；每秒仍读电池/CPU/status。没有「本可以停掉却仍空转」的独立循环，1 s 拍是 status 判活（3 s 超时）的硬需求。
- **模块（LSP 注入散热器 app 进程）**：`startPeriodicStatusWrite` 线程常驻（`MainHook.java:561-597`），每 1 s：写 status（见 A4 模块部分）+ `checkCommandStall()`（`:2904`）→ `isTempStopFresh()`（`:2878-2896`，2 次 `stat` + `open/read/close`）+ 2 次反射 getter。断连时另加每 1 s `maybeClearStuckControllerState()`（`:780-803`，2 次反射字段读取）；重连间隔亮屏 5 s / 息屏 10 s（`:220-221`）。息屏期间仍在跑，只是节流。
- **原生 UI**：页面不可见即停（`ChartFragment.startRefresh/stopRefresh` `:267-280`，`setPageHidden`；`LogFragment` 同构；`onDestroyView` 还 `removeCallbacksAndMessages(null)`）。无残留定时器。
- **lite WebUI**：定时器只在切 tab 时清（`app.js:2398-2417`）；`WebActivity` **没有 `onPause/onResume`、也没调 `webView.onPause()/pauseTimers()`**（`WebActivity.java` 仅 `onDestroy`）→ 停留在曲线/日志页后把 App 切后台，`chartPoll`（1 s）/`logPoll`（1 s）仍可能继续（Chromium 会限制后台定时器频率，但不保证停）。这是**本可以停掉**的一组循环。
- 可降频候选：status 写 1 s → 2 s（daemon 超时 3 s 不变）；`isTempStopFresh` 移到「疑似停滞」分支内；CSV `fflush` 1 s → 2 s；lite 增加 `visibilitychange`/`pauseTimers`。

### A3 曲线 CSV

- 写入频率：**1 行/秒**（`append_webui_row()` `:5076`/`:5082`，每行后立即 `fflush`）。
- 每行字节数：`WEBUI_ROW_FMT`（`:389`）12 列，典型 **54 B**（epoch 10 + 11 个逗号 + 约 42 位数字 + `\n`），区间 50–58 B。
- `fflush`：每行 1 次（`:5082`）；断联不写（`:5059`）。
- 压缩：每追加 60 行（≈60 s）一次（`:5021`、`:5101-5123`）——`fopen("r")` 读约 **780 行 / 42,120 B**，`fopen("w")` 写回 **720 行 / 38,880 B**；压缩缓冲 `char buf[720][128]` = **92,160 B 栈帧**（每分钟一次）。
- 长期运行：
  - 文件大小**恒定上界 780 行 ≈ 39–42 KB**，不会增长；
  - 每分钟 ≈ **81 KB 读写 + 1 次整文件截断重写**；每天 ≈ **60 MB 读 + 56 MB 写**（页缓存脏页口径），每月 ≈ 1.7 GB；
  - 相对 eMMC/UFS 的 TBW 可忽略，但「每分钟一次全文件重写 + 60 次 `fopen`」是固定的周期噪声，且 `fopen("w")` 截断窗口内读者可能看到空/半截文件（正确性问题，阶段一范围）。
  - 长期无磁盘增长风险；主要代价是写入放大与 92 KB 栈帧。

### A4 UI 绘制

**原生曲线（`ChartView`）**

- `onDraw` `:1187-1306`：**每帧 0 个 Java 对象分配**（无 `new`、无字符串拼接；刻度文本、Path、圆点均在 `rebuild` 生成）。每帧只做 `Paint.setColor/setTextSize`（无分配，但 `setTextSize` 每帧会刷新 native 字体度量）+ 约 7 条 `drawPath`（默认窗口 360 点/条）+ 8–10 次 `drawText`。**onDraw 内无任何 IO。**
- 每秒 `rebuild()`（`:310`，由 `setData` `:225-234` 触发）：新建 **7 个 `Path`**（9 系列中 `cold`/`cpu` 默认关；`pid` 另有单独 Path）、`ChartWindow.of`（`:31-71`）4 个 360 长数组（`samples/u/gap/broken`，`gap` 为临时）、6–8 个刻度 `String`（`String.valueOf` `:665/:691`）、约 10 个 `ChartDotOp`/`ChartLabelOp`。合计约 25–35 个对象 + 25 KB/秒。
- 数据侧更重：`ChartFragment.loadNow()` `:283-306` **每 1 s 新起一个 `Thread("ww-chart")`**（`worker.isAlive()` 只防重入，不阻止每秒新建），线程内 `AppFiles.probe`（`stat`+`access`）→ `readTailText`（`TAIL_BYTES=256 KB`，实际文件 ~42 KB）→ `ChartDataset.parse`（`:84-127`）：`text.split("\n")` ≈780 个 String + 每行 `split(",")` ≈9,360 个 String + 9–10 个 `Integer`（≈7,000 个装箱）+ 780 个 `ChartSample`。**估算 300–500 KB/s、约 1 万对象/秒的垃圾**，仅在曲线页可见时产生（离开页面即 0）。

**日志列表**

- `LogFragment` 每 2 s 新起线程（`:312-325`）+ `stat/access`；`LogTailReader` 先比 `size:mtime` 指纹（`:116-120`），**内容没变直接返回 `unchanged`，不重建列表**（`applySnapshot` `:334-337`）。
- 内容一变就全量重建：最多 **3000 行**（`MAX_LINES`）= 3000 个 `LogLine` + 3000 次 `LogClassifier.classify` + `notifyDataSetChanged()` 全量重绑（`LogListAdapter.submit` `:67-72`）。日志文件 16 KB（调试 200 KB）上限内的整读。
- 无每帧 IO；`onDraw` 不涉及。

**状态页**

- 每 5 s（`PERIODIC_REFRESH_MS` `:74`、`:654-658`）一趟：新线程（`:565-579`）+ `Deployer.probe()`（`Deployer.java:420-436`）= **一次 `su` 会话 + 一段 shell**（`stat`、`command -v`、`md5sum`（stat 缓存命中时跳过）、`bin_pid_ok`、`wd_match`，`probeTail` `:1431-1509`）。默认快路径命中时约 4–8 次 fork/exec；PID 为空或缓存失效时回退 `ls -l /proc/[0-9]*/exe`（≈进程数次 `stat`）。即 **12 趟 root shell/分钟**。

**lite WebUI（`app.js`）**

- 曲线页 `chartOpen` → `setInterval(chartPoll, 1000)`（`:1793`）。每拍：
  1) `call('chartData')` → `WebBridge.tail` `:279-285` 读 200 KB 上限（实际 ~42 KB）+ `JSONObject` 转义整段文本；
  2) `chartIngest` `:1477` 对**全部 780 行**重新 `split`+`parseChartLine`（每行 1 个 `parts` 数组 + 1 个 `nums` 数组 + 1 个对象，约 2,300 个对象/秒；只有最后 1 行是新的）；
  3) `drawChart` `:1558` 全画布重绘，默认 6 系列 × 360–720 点 ≈ **2,000–4,300 次 `lineTo`/秒**。
- 日志页 `logPoll` 1 s（`:1822`）读 16 KB（调试 200 KB）；`logIngest` 只追加新行（增量正确），但 `box.textContent = lines.join('\n')` 每次新行都整段重写 DOM 文本（≤3000 行）。
- 状态页 `statusPoll` 5 s（`:1985-1999`）→ 桥侧 `probe()`（`WebBridge.java:107-116`、`:143-169`），即每 5 s 一趟 root shell（同状态页）。
- 所有 `setInterval` 只在切 tab 清理，**无页面可见性门控**（同 A2）。

## C 采样指引（真机命令 + 期望读数）

> 全都只读；`PID` 用 `pidof tempctrl`。`strace` 若机型未自带，用第 5 条的 perfetto 代替。

### C1 daemon 每秒系统调用画像（验证 A1 的 3 open / 4 stat / 13 read）

```sh
adb shell su -c 'timeout 20 strace -f -c -p $(pidof tempctrl)' 2>&1 | tail -20
```

期望：`openat` ≈ 60（3/s×20）、`newfstatat/fstat` ≈ 80、`read` ≈ 260、`lseek` ≈ 200、`write` ≈ 40；`clone/execve` 在**没有下发**的 20 s 内应为 0–2。若 `execve` 明显多，对照 B 表第一行（RAMP 的 5 份广播）。

### C2 daemon CPU 占比与唤醒（验证「1 s 拍几乎不耗 CPU」）

```sh
adb shell 'P=$(pidof tempctrl); a=$(awk "{print \$14+\$15}" /proc/$P/stat); sleep 10; b=$(awk "{print \$14+\$15}" /proc/$P/stat); echo jiffies=$((b-a))'
```

期望：10 s 内 **≤ 20 jiffies（≤2% 单核）**；若明显偏高，看 C1 是否出现 `execve` 突发（广播）或 `/proc` 扫描。

### C3 曲线文件与日志的真实 IO（验证 A3）

```sh
adb shell 'F=/data/data/com.example.waspwingtempctrl/files/tempctrl_webui.data; \
  P=$(pidof tempctrl); grep -E "read_bytes|write_bytes|syscr|syscw" /proc/$P/io; \
  stat -c "%s %i" $F; sleep 60; stat -c "%s %i" $F; \
  grep -E "read_bytes|write_bytes|syscr|syscw" /proc/$P/io'
```

期望：大小在 **38,880–42,120 B** 之间摆动、inode 不变；60 s 内 `read_bytes` 增量 ≈ 40 KB、`write_bytes` ≈ 40–80 KB（页缓存可能让 `read_bytes` 偏小，属正常）。

### C4 曲线页帧时间与内存（验证 A4/A5）


期望：帧间隔集中在 16.7 ms（60 Hz）或 8.3 ms（120 Hz）；`Janky frames` 比例低。若每次数据刷新出现 >32 ms 的尖峰，指向 B 表第 2 行（每秒重解析+重建 Path）。间隔 30 s 再取一次 `meminfo`，Dalvik Heap 应回到同一基线（有界），不呈单调增长。

### C5 广播频率与后台定时器（验证 B 表第 1/4 行）

## D 已核实无问题的地方

1. `ChartView.onDraw`（`:1187-1306`）**零 Java 分配、零 IO**；全部几何（Path/刻度文本/圆点/断联空白）在 `rebuild()` 预计算并缓存，与类头「性能硬约束」注释一致。

3. 5 s 控制块**确实复用** 1 s 采集缓存（`cached_batt_raw`、`cooler_*`、`cached_cpu_now` 路径），没有把 sysfs/status 重读带进控制周期。
4. `is_app_alive` 复用 `read_cooler_params` 的 `fstat` mtime，省掉每拍一次 `stat`（`:2859`、`:2143`）。
