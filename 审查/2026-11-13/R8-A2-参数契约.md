## A. 十条横切判据逐条结论

### A0 `check_params.py` 六项检查（A–F）覆盖与缺口

| 项 | 覆盖 | 主要缺口 |
|---|---|---|
| A 产物可复现 | 4 产物逐字节重跑比对（`params.json` / `profile.conf` / 逻辑说明参数表 / `params_generated.h`） | 与定义同源，语义正确性不覆盖；生成物是否被版本控制不检查 |
| B 产物自洽 | 59 键、必需字段、单字段 min≤default/factory≤max、分组、enum options、table 行 | 不校验跨字段约束（如 `FAN_RPM_RANGE` 最低<最高、`PID_COLD_RANGE` 下限<上限、`COLD_RPM_MAP` 起始<上限）；不校验 `unit`/`rangeNote` 与 `fields` 的语义一致；不校验 `requires` 目标是否为开关、`hiddenWhen` 语义 |
| C 三源无漂移 | 键集合/顺序、C 默认值与 clamp、包名五处、compat、crossChecks | 缺失文件只报 INFO（实际已有 3 处路径失效，见 S2-1）；`audit.cVars` 名不存在只报 INFO（S2-2）；只核对参数表区间，不核对文档正文；只知「C 是否解析」，不知「是否运行期使用」 |
| D 形态自检 | 头文件括号/X 宏实参/格式串、D3 层默认值表覆盖面与复位落点 | 不检查生成宏是否被 C 引用（103/121 个无引用，见 S3-1）；不覆盖多值键手写 clamp 与 def 的绑定方式（只靠 C 审计字面量） |
| E 跨端对拍 | `ki_cut.h` 求值 vs `ki_cut_golden.json` 40 例 | 只覆盖 PID_CUT 求值，不覆盖 `tempctrl.c` 的解析路径；本机无编译器即跳过，只有 CI 执行 |
| F 缓冲护栏 | `load_config` 的 `char line[640]` ≥ PID_CUT 满 32 点行 | 只查 `load_config`；迁移函数自己的 `line[640]`、`out[600]` 未纳入（S3-11） |

**总评**：A–F 把「定义 → 生成产物」和「定义 → C 字面量」两条链钉得较死；缺口集中在「产物是否被真正使用」「audit 元数据自身是否真实」「跨文件路径是否仍有效」「文档正文与计数」。

### 1 契约一致性

**结论：存在 6 类不一致/缺口**，均为可定位问题，不是全面失配：

1. `params.def.json` 的 3 个核对面仍指向 `lsp模块/app/...`，文件已迁到 `lsp模块/core/...`；R4/R6 的包名与私有目录核对被 INFO 静默跳过（S2-1）。
2. `audit.cVars` 的 `PERF_ENABLED → perf_enabled`、`SYSFS_ENABLED → found_sysfs` 在 C 中不存在，两个总开关的默认值核对永不执行（S2-2）。
3. 生成头 121 个宏中 103 个无 C 引用；多值键与 PID 层 clamp 仍是 C 手写字面量（`tempctrl.c:750-867`），与「C 端零改动」的文档口径冲突（S3-1）。
4. 旧键合并/清理的守卫不完整：`APP_LAUNCH_TIMING` 单值会压掉旧 `APP_WATCHDOG`（S2-3）；清理旧键可删掉尚未迁移的 `APP_LAUNCH_*` 迁移源（S2-4）。
5. `PID_CUT_<n>` 簇号后缀未做整串校验，`PID_CUT_2abc` 会被当作簇 2 生效（S2-5）。
6. 文档计数与少量措辞漂移（S3-2/3/5/6/14）。

### 2 资源生命周期

**结论：无**。`params.json` 位于 `:core` 资产，GUI（`app`）与 lite（`app-lite`）均 `implementation(project(":core"))`，资产随 APK 合并；`WebBridge.defsCache` 缓存不可变资产、`ConfigStore` 以文件指纹失效 memo，均无泄漏或陈旧读取。参数文件热重载与写回都走临时文件 + `rename`（`tempctrl.c:3554-3571`、`ConfigStore` 原子写）。

### 3 静默失败

**结论：命中 7 处**：

- 3 个 audit 核对面文件不存在 → INFO 跳过；`check_params.py` 只打印 ERROR，CI 完全看不到 INFO（S2-1、S3-16）。
- `perf_enabled` / `found_sysfs` 不存在 → 「未找到静态初值」INFO 跳过默认值核对（S2-2）。
- 旧 `APP_WATCHDOG` 被新键单值压掉且迁移删旧行（S2-3）。
- 清理旧键删除迁移源（S2-4，有备份，可恢复）。
- `PID_CUT_2abc` 被当合法簇号（S2-5）。
- `config_read_path` 超长值静默截断（S3-10）。
- 临时停止 boot 标记写失败每 5s 静默重试、无日志（S3-13）。
- 另：多值键只给一个值时按 `n>=N` 部分生效/整键不生效，且无提示；这是文档已声明的「必须同给」语义，记入 D 而非缺陷。

### 4 并发与竞态

**结论：命中 1 处**。daemon 的「旧键迁移写回 / 临时停止失效写回」与 app 的 `ConfigStore.setAll` 都对同一 `profile.conf` 做读-改-写，只有 `rename` 原子性、没有跨进程锁；后写者覆盖先写者。触发窗口小，但会丢一次配置修改（S2-6）。单写者内部（`publish_uiprefs`、`.tmp`/`.tmpstop`/`.mig`）未发现其它竞态。

### 5 状态机完整性

**结论：基本完整，无新增缺陷**。已核对：`last_perf_enabled/last_sysfs_enabled` 的 1→0 边沿复位；`CFG_PERF_DEFAULTS` / `CFG_SYSFS_DEFAULTS` 覆盖 int 位、路径键单独复位；`temp_stop_enabled` 的 boot_id 标记、重启失效写回与失败重试；`launch_timing_seen` / `legacy_launch_seen` / `rescan.legacy_seen` / `legacy_pidcut_seen` 的每轮清零；`migrate_give_up` / `launch_migrate_give_up` 的一次性放弃（有注释，属有意设计）。唯一状态问题是 §4 的跨进程写回竞态。

### 6 输入边界

**结论：命中 4 处**：

- `PID_CUT_2abc` 被当簇 2（S2-5，整串校验缺失）。
- 路径/亲和值超过固定缓冲静默截断（S3-10）。
- F 护栏只覆盖 `load_config` 的读行缓冲，迁移用缓冲未覆盖（S3-11）。
- `KI_CUT_SMOOTH` 前缀匹配未校验长度，`KI_CUT_SMOOTH_X` 被静默忽略（S3-12）。
- 另：多值键部分值被静默接受（`n>=1` 即生效）或整键不生效（需 `n>=2`），无日志；文档已声明，不单列缺陷。

### 7 旧键兼容层

**结论：仍需保留，但清理侧有缺口**。

- `APP_LAUNCH_COOLDOWN` / `APP_WATCHDOG`：`tempctrl.c:982-998` 永久读 + `1098-1114` 合并 + 一次性迁移。它们是迁移源，必须保留；但 `compat.cleanup.exact`（`params.def.json:57`）把它们当「恒可删」，`ConfigStore.guardAllows` 对整键族直接放行（`ConfigStore.java:499-502`），可在迁移前删除（S2-4）。
- `KI_CUT_<n>`：`tempctrl.c:3498-3505` 读兼容 + 迁移写回，保留；`KI_CUT_SMOOTH` 只用于「不报未定义」，迁移会删行，可在下一版本退役读兼容（S3-12 的越界前缀匹配应一并修）。
- `UI_CHART_SWAP` 单值、`UI_CURVE_FILTER` 两值、`APP_LAUNCH_SCREEN_GATE` 三值：读取端兼容且无迁移写回（`ChartConfig.java:127-152`、`ConfigKeyRow.java:642-650`、`tempctrl.c:1031-1052`），存量配置仍可能命中，保留。
- `compat.renames` 中的已删键只服务界面标注，无读取兼容，保留成本低。

### 8 重复与死代码

**结论：命中 4 类**：

- 生成头 **103/121 个宏无引用**：`CFG_DAEMON_KEY_COUNT` / `CFG_WEBUI_KEY_COUNT` / 100 个 `CFG_MIN/MAX_*` / `CFG_DEFAULT_LOG_FILE`；实际只有 `CFG_PERF_INT_KEYS`、`CFG_SYSFS_KEYS`、`CFG_PERF_DEFAULTS`、`CFG_SYSFS_DEFAULTS`、4 个路径默认宏、8 个 PID_CUT 宏被用（S3-1）。
- 2 个键「解析了但没人读」：`BATT_CURRENT_PATH`、`BATT_CURRENT_DIVISOR`（`tempctrl.c:107/112` 仅有声明与复位；`SK_PATH/SK_INT` 会写入变量，但全文件无读取点）。文档明示为预留，见 D。
- lite 的 `enum` 渲染分支（`app.js:577-592`）不可达：`MAIN_GROUPS` 不含 `webui`，`WEBUI_KEYS` 不含 `UI_START_PAGE`。
- lite 的曲线常量兜底（`CHART_WINDOWS`、`3/15`、`3000`、`40/190`）与定义默认值重复；作为无 `params.json` 时的兜底可接受，但存在两处默认值来源。

### 9 文档偏差

**结论：命中 6 处**（详见 S3-2/3/5/6/14）：

- 键数：`对齐报告.md:3`、`参数名与说明审查.md:3` 写「60 键」；`参数合并候选.md:3` 写「61 键」；`lsp模块/app/逻辑说明.md:555/607/981` 写「60键 / 55键 / 设置页 11 键」。实际 59 键，设置页 13 键（webui 8 + control 5）。
- `params.def.json:18` 写「WebUI 组 9 键」，实际 8 键。
- `params.def.json:16` 的产物路径仍写 `app/src/main/assets/params.json`，实际在 `core/src/main/assets/params.json`。
- `lsp模块/daemon/逻辑说明.md:299` 称冷值非整数「整行忽略」，代码实际「只忽略该点，其余点照常装载」（全部点无效才整行忽略）。
- `RATE_LIMIT_FAN` 防抖阈值单位写作 `RPM/控制周期`，语义是 RPM 距离（DEF 的 `desc`/`rangeNote` 也重复了同一错误）。
- `profile.conf:8` 头部段标汇总写 `[0]日志 / [1]性能参数`，正文实际为 `[0] 日志调试 / [1] 性能总开关`。

### 10 测试缺口

**结论：命中 5 类**：

- E 依赖宿主 C 编译器；本机无 cc/gcc/clang 时只跳过，PID_CUT 求值的跨端对拍只有 CI 覆盖。
- 无自动化测试覆盖 `tempctrl.c` 的多值键解析（`parse_pid_cfg` / `parse_common_cfg` / `SK_ZONE` / `SK_RESCAN`）与旧键迁移、清理守卫；`PID_CUT解析回归测试.py` 只测 PID_CUT 解析且未接 CI。
- 无跨字段断言（`FAN_RPM_RANGE` 最低<最高、`HOT_RPM_MAP` 最低<最高、`PID_COLD_RANGE` 下限<上限、`COLD_RPM_MAP` 起始<上限）。
- 无 unit/rangeNote 文本与 fields 数值的语义核对（debounce 单位错误即由此漏过）。
- 无 lite WebView 的自动化测试；`field.bool`、写入失败、混合 pending 三处只能靠人工。
