## A. 十条横切判据逐条结论

1. **契约一致性**：`params.json` → `KeyMeta` → 六型渲染器的键名/类型/默认值/范围链路一致；`default`（代码默认）与 `factory`（出厂）分列，表单回填用前者、重置用后者，与 `ConfigStore` 一致；`assess` 的钳制边界与定义同源。**不符合项**：平台 API 契约 `minSdk 25` 与 `Set.of`（API 30+）冲突（S1-1）；`UI_CURVE_FILTER` 旧两值格式的表单映射与运行时 `ChartConfig` 不一致（S2-1）；"界面自用"徽标按"有任一"覆盖整组（S3-1）。
2. **资源生命周期**：`HintOverlay` 的 static `current`、返回键回调、滚动监听、`TableRenderer` 的 1Hz ticker 都在移除/`detach` 时清理；`ConfigFormController.io` 在 `onDestroy` 关闭；输入框监听无静态持有。**不符合项**：`ConfigPreInflater` 的 static `instance.owner` 永久持有 Activity（S2-4）；`TableRenderer` 在分组收起（body GONE、行仍 attach）时 ticker 不停（S3-13）。
3. **静默失败**：定义/快照失败有明确上屏；写盘失败有行级 + Snackbar；预制造失败按优化降级（有记账）属有意。**不符合项**：`reloadAsync` / `cleanupLegacyKeys` / `resetGroup` 的 io lambda 未包 `try/catch`，异常逃逸后 UI 无回调（S3-9）；段一 `buildForm` 无兜底（S3-10）；写盘失败后 `pending` 被摘而控件不回退（S3-7）；`onLoadFailed` 把快照读失败写成"参数定义加载失败"（S3-15）。
4. **并发与竞态**：`diskValues`/`pending`/`dueAt` 只在主线程；`io` 单线程保证"读先于其后提交的写"；`ConfigPreInflater` 池的"关门 + 补刀清空"在视图侧成立。**不符合项**：失焦空值的恢复分支不撤销 pending（S2-2）；`cancel()` 拦不住已提交 io 的批次（S2-3）；`applyHeaderValues` 与 `applyReset` 用快照/出厂值直铺，绕过 `effectiveValue`（S3-5、S3-6）。越界：`ConfigStore.memo` 非 volatile 且表单在主线程 `read()`（C 节）。
5. **状态机完整性**：建表 `buildRound`/`rowsPhaseRound`/`revealPending`/`pendingReload` 的幂等与轮次守卫完整；段二失败不回退已露卡头；`HintOverlay` 的 showing/forwarding/outsideGesturePending/removeAfterGesture 四态经逐事件走查闭合。**不符合项**：段一异常无兜底（S3-10）；枚举"表外值"在二次上屏后不清旧选中（S3-3）；成功写盘/重置不清旧错误态（S3-4）。
6. **输入边界**：`parseInt` 对空/非数字返回 null（不写盘），超 int 范围夹到边界，`assess` 再按字段 min/max 钳制；路径空值不写、含 `#` 告警；多值缺项回填 `defaultValue` 而非 0；布尔子开关切换时"没输完"的数字框回退当前有效值。**不符合项**：失焦空值后的隐藏 pending（S2-2）；超长标签折行被垂直中心钉裁顶（S2-5）；枚举表外值旧选中（S3-3）。
7. **旧键兼容层**：`UI_CHART_VIEW` 的旧键回退（`UI_RPM_AXIS_MIN`/`UI_PID_MARK`）与 `ChartConfig` 同口径，且只在该值就是磁盘快照值时回退；`UI_CHART_SWAP` 单值展开为两槽、保存写两段、重置/默认回填均覆盖；`GATE_LE` 在本包无残留；`WD_KEEPALIVE` 不是已删键（当前 `control` 组有效键，`params.def.json:2306`）。**不符合项**：`UI_CURVE_FILTER` 旧两值未展开（S2-1）；更早的 `WEBUI_RPM_AXIS_MIN` 无读取路径（S3-11）；`APP_LAUNCH_TIMING` 的旧两键迁移只在 daemon 侧（C 节，非本包缺陷）。
8. **重复与死代码**：`isUnsatisfied` 的"行内压暗 / 卡头徽标"单一判据、`refreshBadges` 的"行未建全"分支、`ConfigPreInflater` 六个 Renderer 的备料清单均对齐。**不符合项**：无参 `refreshDependencyState()` 无调用方（S3-14）；行级"界面自用"说明分支在"有任一"判据下恒不可达（并入 S3-1）；`UI_CHART_VIEW` 旧键映射在 `ConfigKeyRow` 与 `ChartConfig` 各抄一份（S3-12）。
9. **文档偏差**：`逻辑说明.md` 的 §6.1 示例写 60 键、§6.5 写 55 键，实际 `check_params.py` 为 59；`params.def.json:18` 写"WebUI 组 9 键"，实际 8 键；`ConfigKeyRow.java:263` 写"组内所有键都不被读取"而 `ConfigGroupBinder` 用"有任一"；§6.1 "写进控件的值取当前有效值"在 `applyHeaderValues` 有例外（S3-5）。前两项与 R3 已报的 60/55 漂移同源（C 节）。
10. **测试缺口**：`lsp模块/app`、`core` 均无 `src/test`/`androidTest`；旧格式映射（`UI_CURVE_FILTER`/`UI_CHART_SWAP`/`UI_CHART_VIEW`）、写队列"已提交后撤销"、`Set.of` 的 API 下限、长标签布局均无回归保护；`check_params.py` 只校验定义与派生副本，不覆盖界面映射。本次全部结论为静态核对，未运行验证。

## C. 越界发现（归属包 + 一句话）

- **配置存储包（R3-A2 已报 S2-1）**：`ConfigStore.removableKeys` 对 `compat.cleanup.exact` 的 `APP_LAUNCH_COOLDOWN`/`APP_WATCHDOG` 没有"新键存在才可删"守卫（`ConfigStore.java:445-461,483-502`），而它们是 `tempctrl.c:3876-3932` 的迁移源；本包 `ConfigFormFragment:350-398` 的"清理旧版遗留键"按钮是触发入口。

- **曲线包**：`ChartConfig.java:118-175` 与 `ConfigKeyRow.java:662-677` 各维护一份 `UI_CHART_VIEW` 旧键回退逻辑；`UI_CURVE_FILTER` 的旧两值兼容只在 `ChartConfig` 实现，表单未对齐（S2-1 的另一半）。
- **参数定义包**：`params.def.json:18` 的"WebUI 组 9 键"与生成产物 8 键不符；`WEBUI_RPM_AXIS_MIN` 在 `compat.renames`（`:67`）登记为已并入 `UI_CHART_VIEW`，但无任何读取路径。

- **钩子/daemon 包（有意保留，非缺陷）**：`GATE_LE` 仍存在于 `MainHook.java:62` 与 `tempctrl.c` 的 uiprefs 转写，是给旧版模块的协议兼容，不是表单层残留已删键。

## D. 已核实无害（可疑但查证不成立）

- **`UI_CHART_VIEW` 的旧键回退身份判断**：`value != host.diskValue(meta.key)` 的引用比较成立——`applySnapshot` 先 `rememberSnapshot` 再 `effectiveValue`，无 pending 时返回的正是 `diskValues` 里那个对象；`ChartConfig.chartViewSlot` 用 `present && size>i` 的同口径，两处一致。`applyReset` 虽把出厂值先塞进 `diskValues` 再造"身份"，但成功 `setAll` 后 `rememberWritten` 已把新文本写进 memo，`present` 为真，不会误走旧键。
- **`UI_CHART_SWAP` 旧单值**：`fillValueAt` 对 `size()==1` 展开两槽；保存时 `MultiRenderer.read` 永远读两槽并写两段；重置用 `factoryValue=[0,0]`、缺项回填 `defaultValue=[0,0]`。读/写/重置/默认四条路都覆盖。`params.def` 的"不回写"指运行期解析不主动改写，不否定用户编辑后的两段写回。
- **`GATE_LE` / `WD_KEEPALIVE` 的"已删键"前提**：表单六个文件与布局对 `GATE_LE`/`UI_GATE_LE` 零引用；`WD_KEEPALIVE` 是 `control` 组现行键（`params.def.json:2306`，`profile.conf:295`），不是死键。任务描述里的"已删"对后者不成立。
- **`APP_LAUNCH_TIMING` 旧格式**：迁移由 daemon 在配置加载时完成（新键优先、旧行删除），且旧键在 `compat.daemonAccept.exact` 中不进入"未定义键"；表单只读新键属预期分工。真正的风险是 R3 S2-1 的"daemon 未跑过时清理旧键"，已归 C 节。
- **`HintOverlay` 触摸状态机**：逐事件走查——卡外 DOWN 必消费；tap 在 UP 收起且不转发；越 slop 或多指先 `hide()` 再补投缓存的 DOWN 与当前 MOVE；淡出结束若 `forwarding` 则留壳到 UP 再 `remove()`；淡出期间无手势时 `onTouch` 返回 false 放行下一次点击。未发现穿透或断转发。
- **`ConfigWriteQueue` 的 `dueAt ⊆ pending` 不变量**：`schedule`/`cancel`/`finish` 三处同步维护；`finish` 对"写盘期间以相同值重排"的键会连带摘 `dueAt` 并重排定时器，注释与实现一致。
- **`WrapRowLayout` 两列布局**：halfLine 的"先量自然宽、再按半行/整行二选一重量"在 measure/layout 同一 `Pass` 内完成；窄屏/长内容只会让该行退回整行，不会半格溢出；两格 + 一个列距恰好等于 rowLimit（整数除法下 ≤）。
- **`ConfigPreInflater` 视图池**：`closed` 的"先判后放 + 放后补清"在并发交错下保证 release 后池空；消费侧取不到即现场 inflate，失败只削收益。泄漏只在 `owner` 字段（S2-4），不在池。
- **设置页控制组的动作行重复添加**：`onGroupRowsBuilt` 只由 `buildRowsPhase` 每轮每组调一次，`rowsPhaseRound` 守卫了 pre-draw 与兜底延时两条路；提前 `buildRows`（默认展开）不会重复追加。
- **写盘与读盘的先后**：控制器只有一个 io 串行域，读任务总在其后提交的写任务之前完成；主线程 post 顺序因此不会出现"旧快照晚于新写回执"。
- **`commitSwitch`/`commitOption` 的程序化回填防护**：都用 `effectiveValue` 比对同值不写；`suppressChange`/`suppressMaster` 屏蔽程序化回调。
- **`restoreInputs` 用磁盘值而非 effective**：正常输入变化会先由 Watcher 的 `cancel` 撤 pending，故多数路径无差异；只有"先拨布尔、再碰空数字框失焦"这一条漏网（S2-2）。
- **`UI_HINT_AUTO` 现读现用**：设置页离开时 `onPause` 已 flush，配置页获焦时磁盘值已更新；无"改了不生效到重启"的问题（主线程 stat 的开销另见 S3-8）。
