# 参数名与说明审查（用户视角）

> 范围：`参数定义/params.def.json` 全部 59 键 / 6 组。
> 方法：第一步只读 `label` / `desc`（必要时带 `docDesc`），模拟第一次用模块的人；第二步逐个对照 `lsp模块/daemon/tempctrl.c`、`lsp模块/app/src/main/java/...`、`lsp模块/core/src/main/assets/deploy/b6x-tempctrl.sh` 核实；第三步评 `key` 与 `label`。
> 界面实际渲染：参数行显示 `desc`，说明浮窗显示 `docDesc`（“作用”）与 `confNote`（“填写指导”）。因此 **`desc` 是第一道门槛**，`docDesc` 只能在用户点开浮窗后补救。
> 本文只做审查，不修改 `params.def.json` 与任何生成产物。

---

## 0. 总评

**整体问题类型（按数量排序）**

1. **说明不完整（最多）**：约 23 个键只写了概念或公式，没写默认值、范围、单位或生效条件。单值控件的范围/单位在界面上能靠控件补足，但多值键和“改了会怎样”的后果仍只能靠文字，`desc` 不写就只能点浮窗。
2. **术语未解释 / 标签过简**：约 7 个键的 `label` 使用工程缩写或过短（`PID`、`CPU平滑`、`映射平滑`、`速度映射`、`KDP`、`KI`、`冻结阈值`），首次使用者无法从名称判断对象。“热端”“制冷强度档位”也未在定义里解释。
3. **依赖未写 / 写错（影响最大）**：`BT_AUTO_ENABLE_SEC`、`UI_GATE_LE`、`WD_KEEPALIVE` 三个键实际都受 `APP_LAUNCH_ENABLED` 控制，但说明里没写；`BT_AUTO_ENABLE_SEC` 的 `docDesc` 还反向写了“任何模式生效”。
4. **名称口径不统一**：`UI_AUTO_UPDATE` 的 `label` 仍是“自动更新”，与“设备端部署产物重新部署”的实际语义不符；同一概念在定义里混用“自动更新 / 自动部署 / 重装 / 部署”。“断联 / 断连”也混用（11 次 / 4 次）。
5. **真正的实现矛盾只有 1 处**：`COLD_RPM_MAP` 声称“起始强度 ≥ 上限则整段不生效”，实现却是返回 0 后仍以最小权重参与冷/热加权，会把风扇目标往下拉。

**统计**：说明可懂性 好 33 / 一般 23 / 差 4；与实现一致性 一致 55 / 偏差 4 / 错误 1。

**最该先修的 3 个键**

1. **`UI_AUTO_UPDATE`** —— 名称与“部署”口径（任务已点名；当前工作树里 `label` 仍为“自动更新”，见 §2.1 的勘误）。
2. **`BT_AUTO_ENABLE_SEC`** —— 依赖写错，用户关掉“自动拉起 app”后会以为这个开关坏了。
3. **`CPU_FILTER_ALPHA`** —— 唯一一个 `desc` 连“在平滑什么”都没写的键，基本不可用。

`COLD_RPM_MAP` 是第 4 个必修项，但它需要先拍板“改代码还是改说明”（见 §2.5）。

## 2. 必修项（可直接替换文本）

### 2.1 `UI_AUTO_UPDATE` —— 名称与“更新/部署”口径

**事实勘误（重要）**：任务说明称展示名已改为“自动部署”，但当前工作树里 `params.def.json` 的 `label` 仍是 **“自动更新”**，生成的 `lsp模块/core/src/main/assets/params.json` 同此；`desc` 已改用“自动重装/部署”，`docDesc` 与 `confNote` 仍写“自动更新”。改名尚未落到单一来源。

**问题**：这个键做的是“设备上的守护进程/脚本与 APK 内不一致时重新部署”，不是“更新 app 版本”。“自动更新”会让用户以为是在线升级模块或飞智 app。

**替换文本**

- `label`：`自动部署`
- `desc`：
  > 自动部署（默认开启）：设备上的守护进程与开机脚本和 APK 内不一致时，开机脚本会在开机时自动重装（重装会重启守护进程）；开机时没成功，还会在看门狗周期内重试，次数有上限。关闭后不在后台自动重装，只在 app 内弹窗请求你手动部署。
- `docDesc`（把“自动更新”全部替换为“自动部署”，其余保留）：
  > 自动部署（0/1，默认 1）：开机脚本在开机时先比 APK 文件的修改时间、有变化再校验内容，不一致就自动重装并重启守护进程；时间戳未变则整段短路（其后的看门狗周期内还会再试，次数有上限）。值为 1 时 app 侧发现不一致也静默重新部署（不弹窗），关闭则退回弹窗请求。本键由开机脚本直接读配置文件，界面与脚本不共享内存。
- `confNote[0]`：“自动更新（0/1，默认 1）……”改为“自动部署（0/1，默认 1）……”。

**连带（不在本次修改范围）**：`lsp模块/app/src/main/res/values/strings.xml` 的 `status_auto_deploy_log` 等硬编码文案仍写“自动更新”，改名后需同步；状态页首行读取的是 `label`，会自动跟着变。

### 2.2 `BT_AUTO_ENABLE_SEC` —— 依赖写错

**实现依据**：`tempctrl.c:861` 把发布值算成 `bt_sec_eff = APP_LAUNCH_ENABLED ? bt_auto_enable_sec : 0`；`tempctrl.c:4621` 的自动开蓝牙动作也要求 `APP_LAUNCH_ENABLED`。

**问题**：`docDesc` 末尾写“**独立于性能总开关，任何模式生效**”，只说了它不受 `PERF_ENABLED` 影响，却让读者以为不受任何开关限制；`desc` 完全没提依赖。

**替换文本**

- `desc`：
  > 断连后自动开蓝牙：后台重连确认蓝牙未开启时自动打开，两次之间至少间隔此秒数（默认 300 秒，范围 0~3600；0 = 关闭该功能）。需先开启「自动拉起 app」；自动拉起关闭时本项运行期按 0 处理（配置值不改，重新开启后恢复）。
- `docDesc`：把末尾的“**独立于性能总开关，任何模式生效**”替换为：
  > **独立于性能总开关；但需「自动拉起 app」开启才生效**（自动拉起关闭时运行期按 0 处理，配置值不改）。

### 2.3 `UI_GATE_LE` —— 依赖未写 + 说法不精确

**实现依据**：`tempctrl.c:860` 的 `gate_le_eff = (APP_LAUNCH_ENABLED && gate_le_enabled) ? 1 : 0`；`MainHook.java:1285` 只在连接期把 `getType()` 报告为 LE。

**问题**：`desc`/`docDesc` 都没写它受 `APP_LAUNCH_ENABLED` 控制；`desc` 说“按蓝牙设备处理”，实际是把设备类型报告为**低功耗蓝牙（LE）**，经典蓝牙并不放行。

**替换文本**

- `desc`：
  > 重连放行（默认开启）：开启后，飞智 app 发起连接期间，把上次连接的散热器地址按低功耗蓝牙（LE）报告，绕开 app 的蓝牙类型检查，使后台自动重连能真正发起连接；关闭则恢复原行为。需先开启「自动拉起 app」；自动拉起关闭时本项运行期按 0 处理。仅对公开地址（PUBLIC）的目标设备有效。
- `docDesc`：在首句后插入：
  > 需先开启「自动拉起 app」；自动拉起关闭时运行期按 0 处理（配置值不改）。

### 2.4 `WD_KEEPALIVE` —— 依赖未写

**实现依据**：`tempctrl.c:4791` 为 `if (!APP_LAUNCH_ENABLED || !wd_keepalive_enabled) return;`。

### 2.5 `COLD_RPM_MAP` —— 说明与实现不一致（需拍板）

**实现依据**：`tempctrl.c:3900-3901`，`range = active_pid_cold_max - cold_map_start; if (range <= 0) return 0;`；`tempctrl.c:3946-3950`，只要热端有效就无条件把 `rpm_cold` 以 `weight_from_rpm(rpm_cold)` 的权重并入加权平均。`rpm_cold = 0` 时权重并不为 0（`weight_from_rpm` 把 0 钳到最低转速，权重 = `fan_rpm_min`），所以结果是把风扇目标往下拉，而不是“只剩热端映射”。

**问题**：`desc` 写“否则这段映射不生效”，`docDesc` 写“≥ 上限时制冷映射整段失效（映射输出 0，只剩热端映射/最低转速）”，都与实际不符；另 `desc` 有“上限，，否则”双逗号笔误。

**两种处置，二选一**

- **方案 A（推荐，若设计意图真是“整段失效”）**：改代码，在 `compute_fan_target()` 里对 `active_pid_cold_max - cold_map_start <= 0` 的情况把冷端权重置 0，只保留热端映射。代码改动不在本次审查范围，需另派。
- **方案 B（若当前行为可接受）**：只改说明。替换 `desc`：
  > 制冷强度到风扇转速的映射（双值：起始强度 指数）。比例 =（当前制冷强度 − 起始强度）÷（制冷上限 − 起始强度），转速 = 最低转速 + 比例^指数 ×（最高转速 − 最低转速）。起始强度默认 40（范围 0~194），指数默认 150（范围 50~500，存储值 ÷100：100 = 直线，大于 100 时低制冷段风扇更慢，小于 100 时低制冷段风扇更快）。起始强度必须小于制冷上限（制冷范围（PID_COLD_RANGE）的上限，默认 190）；若 ≥ 上限，冷端映射输出 0，但仍会以最小权重参与冷/热加权，把风扇目标往下拉。最终转速还会与热端映射按 RPM 加权平均。

  并把 `docDesc` 里的“≥ 上限时制冷映射整段失效（映射输出 0，只剩热端映射/最低转速）”改为“≥ 上限时冷端映射输出 0；该 0 值仍以最小权重参与冷/热加权合并（会把风扇目标往下拉），并非‘只剩热端映射’”。

## 4. 参数名评估

### 4.1 `UI_` 前缀已失真

当前 `UI_` 键分布在三个组：

- `[4] 界面` 7 键：`UI_GAP_SEC`、`UI_ANIM_TUNING`、`UI_RPM_AXIS_MIN`、`UI_PID_MARK`、`UI_CURVE_FILTER`、`UI_START_PAGE`、`UI_PATH_COPY`
- `[5] 控制` 4 键：`UI_TEMP_STOP`、`UI_BACK_HIDE`、`UI_AUTO_UPDATE`、`UI_DEPLOY_ENTRY`
- `[3] 拉起应用` 1 键：`UI_GATE_LE`

`UI_` 已不再等于“界面组”：其中 `UI_TEMP_STOP`、`UI_BACK_HIDE` 由守护进程读取，`UI_AUTO_UPDATE` 由开机脚本读取，`UI_GATE_LE` 在拉起组且由守护进程转写给宿主钩子。

**建议**：改名的迁移成本高（`profile.conf` 存量值、开机脚本 grep、钩子标志文件、`compat.renames` 都要动）。若本轮没有明确收益，**最省的做法是在 `params.def.json` 的 `notes` 里写明**：

> `UI_` 是“界面侧/跨进程”命名空间，不代表所属分组；分组以 `group` 字段为准。

若决定改名，最小集是 `UI_GATE_LE → APP_GATE_LE`（它已在拉起组，且语义是连接放行，不是界面）；`UI_TEMP_STOP → CTL_TEMP_STOP`、`UI_BACK_HIDE → CTL_BACK_HIDE`、`UI_AUTO_UPDATE → CTL_AUTO_DEPLOY`、`UI_DEPLOY_ENTRY → CTL_DEPLOY_ENTRY`。改名前必须先补 `compat.renames` 与 `profile.conf` 迁移，否则存量用户会丢配置。

### 4.2 同概念两种叫法

- **自动更新 / 自动部署 / 重装 / 部署**：统一为“自动部署”，动作写“重装”。
- **断联 / 断连**：定义里“断联”11 次、“断连”4 次。建议统一为“断联”（多数派，且 `UI_GAP_SEC`、`RECONNECT_KEEP_CYCLES` 已用）。
- **制冷强度 / 制冷档位 / 冷值 / 制冷上限**：建议在 `PID_CUT` 首次出现时定义“制冷强度（0~194 档，下文简称冷值）”，其余处统一用“制冷强度”，只在 `PID_CUT` 表格语境用“冷值”。
- **外围开关 / 接口与外围**：label 与组名统一。

### 4.3 label 与 key 含义不完全对应

- `PERF_ENABLED`（perf）→ “性能总开关”：实际是“性能参数层总开关”。
- `SYSFS_ENABLED`（sysfs）→ “外围开关”：实际管 sysfs 路径、缩放系数与日志路径/上限。
- `BATT_BASELINE`（batt）→ “基准温度”：丢了“电池”。
- `UI_GATE_LE`（LE）→ “重连放行”：label 描述效果，key 描述 LE 类型门禁；两者都不算错，但合起来才完整。
- `CPU_FILTER_ALPHA` / `MAP_INPUT_SMOOTH_ALPHA`：key 说 ALPHA（系数），label 说“平滑”（像开关/等级）。

### 4.4 缩写未解释

`KDP`、`KI`、`CH`、`LE`、`AOD` 在定义里首次出现时都没有解释。建议在对应 `desc` 首句给一次中文全称，例如“KDP（比例+速度融合项）”“KI（积分项）”“CH（受控量）”“LE（低功耗蓝牙）”。`AOD` 已在 `APP_LAUNCH_SCREEN_GATE` 里写了“息屏显示”，可留。
