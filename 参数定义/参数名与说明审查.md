# 参数名与说明审查（用户视角）

> 本表按 2026-11-14 的 `参数定义/params.def.json` 编制，共 **60 键 / 6 组**；键数与该文件是唯一权威，键变更时本表需同步。
> **键数随定义更新，本表不写死总数以外的派生数字**（分组计数、各页渲染数等一律由 `params.json` 运行时计算，不在此列）。
> 方法：第一步只读 `label` / `desc`（必要时带 `docDesc`），模拟第一次用模块的人；第二步逐个对照 `lsp模块/daemon/tempctrl.c`、`lsp模块/app/src/main/java/...`、`lsp模块/core/src/main/assets/deploy/b6x-tempctrl.sh` 核实；第三步评 `key` 与 `label`。
> 界面实际渲染：参数行显示 `desc`，说明浮窗显示 `docDesc`（“作用”）与 `confNote`（“填写指导”）。因此 **`desc` 是第一道门槛**，`docDesc` 只能在用户点开浮窗后补救。
> 本文只做审查，不修改 `params.def.json` 与任何生成产物。

## 0. 总评

**统计（60 键）**：说明可懂性 **好 45 / 一般 14 / 差 1**；与实现一致性 **一致 59 / 偏差 1 / 错误 0**。

**与 2026-11-13 版本相比已修复的点**（本轮逐个核实）：

- `COLD_RPM_MAP` 的“≥ 上限整段失效”与实现的矛盾已消除；现说明与 `compute_fan_target()` 的“输出 0 仍以最小权重参与加权”一致。
- `BT_AUTO_ENABLE_SEC`、`WD_KEEPALIVE` 已补“需自动拉起 app 开启”的前置条件。
- `UI_AUTO_UPDATE` 的 `label` 已由“自动更新”改为“自动部署”，`desc` / `docDesc` / `confNote` 口径统一。
- `UI_BACK_HIDE` 已补“自动拉起 / 锁死重启路径同受本开关控制”。
- `DEBUG_PID`、`CPU_FILTER_ALPHA`、`MAP_INPUT_SMOOTH_ALPHA`、`PID_SPEED` 等 label 已补足对象 / 方向。
- 三个旧界面键（LE 放行、纵轴下限、重算标记）已删除；新键 `APP_LAUNCH_TIMING`、`UI_CHART_VIEW`、`UI_CHART_SWAP`、`UI_HINT_AUTO`、`RAMP_SLOTS` 已纳入本表。

**剩余问题（按影响排序）**

1. **`CPU_FILTER_ALPHA` 仍是唯一“差”**：`desc` 只有“首次直取，此后按系数平滑；值越大越跟随原始值”，缺主语、默认值、范围、单位和结果用途。按 §2.1 改写。
2. **`RATE_LIMIT_COLD` 的死区说明是唯一“偏差”**：`desc` 写成“|目标 − 回传| < 死区时升降都不下发”，实际是**冷值与风扇各自判定，两者都在死区内才整体跳过**（`should_skip_dispatch()`）。按 §2.2 改写。
3. **一批 `desc` 仍缺默认值 / 范围 / 单位**：不影响理解，但用户要知道“默认多少、能填多大”必须点浮窗。按 §3.2 补写。
4. **少数 label 仍偏笼统**：`BATT_BASELINE`、`HOT_RPM_MAP`、`HOT_DERATE`、`LOG_MAX`、`UI_TEMP_STOP`、`UI_DEPLOY_ENTRY`、`APP_LAUNCH_TIMING`。按 §3.1 处理。

**最该先修的 3 个键**

1. `CPU_FILTER_ALPHA` —— 唯一“差”，说明基本不可用。
2. `RATE_LIMIT_COLD` —— 唯一“偏差”，死区条件写漏会让用户误判“冷值被冻结”。
3. `HOT_RPM_MAP` —— “热端”未定义、label 未写映射方向，首次使用者不知道它映射到什么。

## 2. 必修项（可直接替换文本）

### 2.1 `CPU_FILTER_ALPHA` —— 说明基本不可用

**实现依据**：`tempctrl.c` 的 `update_cpu_filtered()`（对 CPU 温度做 EMA）与 `cpu_comp_now()`（结果进入 CPU 补偿）。

**问题**：`desc` 只有“首次直取，此后按系数平滑；值越大越跟随原始值”，没有主语、默认值 / 范围 / 单位，也没说结果只用于 CPU 补偿。`label` 已改为“CPU 温度平滑”，问题只剩 `desc` / `docDesc`。

**替换文本**

- `desc`：
  > CPU 温度滤波系数（默认 25%，范围 1~100%）：首次直取原始读数，此后每次按“系数% 新值 + 其余% 旧值”做指数平滑。值越大越跟随原始读数（越不平滑），越小越平滑。结果只用于 CPU 补偿，不改变电池温度主控。
- `docDesc`：
  > CPU 温度滤波系数（百分比，默认 25，范围 1~100）：首次直取原始读数，此后按系数做指数平滑（每次取 系数% 新值 + (100−系数)% 旧值）；值越大越跟随原始值，越小越平滑。结果用于 CPU 补偿（PID_CPU_COMP）的输入，不参与电池温度主控。

---

### 2.2 `RATE_LIMIT_COLD` —— 死区条件写漏

**实现依据**：`tempctrl.c` 的 `should_skip_dispatch()`：`cold_hold` 与 `rpm_hold` 同时为真才 `return 1`（跳过下发）；任一超出各自死区，冷值与风扇一起下发。注释原文：“冷值与风扇各按自己的死区判定（同一套 `within_deadzone`）：两者都在死区内才跳过；任一超出死区 → 冷值和风扇一起下发”。

**问题**：`desc` 的“|目标 − 回传| < 死区时升降都不下发”只说了冷值，读者会以为只看冷值；实际风扇也要在死区内。另缺默认值与范围。

**替换文本**

- `desc`：
  > 制冷强度升降速限速（三值：基础步长 倍率 死区，单位均为制冷强度档位/控制周期）。升速 = 基础步长 + 温差 × 倍率 ÷ 10，降速 = 基础步长 − 温差 × 倍率 ÷ 10（温差 = 电池温度 − 基准温度，有符号）；结果为负时禁止该方向。基础步长默认 15（范围 1~194）、倍率默认 10（范围 1~100，算式内 ÷10）、死区默认 3（范围 1~50）。死区按冷值与风扇各自判定：两者都在各自死区内才整体跳过下发；任一超出，冷值与风扇一起下发。贴近上限/下限时该方向死区豁免（余量 < 向上取整(死区×1.5) 时放行）。
- `docDesc`：在死区句后补一句：
  > 冷值与风扇各自按自己的死区判定，两者都在死区内才整体跳过；任一超出则冷值与风扇一起下发。

## 3. 建议项

### 3.1 label 建议

| 键 | 现 label | 建议 label | 理由 |
|---|---|---|---|
| `PERF_ENABLED` | 性能总开关 | 性能参数总开关 | 它管的是本组参数，不是整机性能 |
| `SYSFS_ENABLED` | 外围开关 | 接口与外围开关 | 与组名对齐 |
| `BATT_BASELINE` | 基准温度 | 电池基准温度 | 组内还有热端温度，必须区分 |
| `HOT_RPM_MAP` | 热端映射 | 热端→转速映射 | 补上映射方向 |
| `COLD_RPM_MAP` | 制冷映射 | 制冷→转速映射 | 补上映射方向（可选） |
| `HOT_DERATE` | 过温削减 | 过温削减制冷 | 削的是制冷上限 |

## 4. 参数名评估

### 4.1 `UI_` 前缀现状

当前 `UI_` 键 12 个，分布：

- `[4] 界面` 8 键：`UI_GAP_SEC`、`UI_ANIM_TUNING`、`UI_CHART_VIEW`、`UI_HINT_AUTO`、`UI_CURVE_FILTER`、`UI_CHART_SWAP`、`UI_START_PAGE`、`UI_PATH_COPY`
- `[5] 控制` 4 键：`UI_TEMP_STOP`、`UI_BACK_HIDE`、`UI_AUTO_UPDATE`、`UI_DEPLOY_ENTRY`
- `[3] 拉起应用` 0 键（旧 LE 放行键已删除）

`WD_KEEPALIVE` 在控制组但不用 `UI_` 前缀。

`UI_` 已不再等于“界面组”：`UI_TEMP_STOP`、`UI_BACK_HIDE` 由守护进程读取（`daemonConsumes=true`），`UI_AUTO_UPDATE` 由开机脚本读取，`UI_DEPLOY_ENTRY` 仅界面读取。

**建议**：改名成本高（`profile.conf` 存量值、开机脚本 grep、钩子标志文件、`compat.renames` 都要动）。若本轮没有明确收益，最省的做法是在 `params.def.json` 的 `notes` 里写明：

> `UI_` 是“界面侧/跨进程”命名空间，不代表所属分组；分组以 `group` 字段为准。

若决定改名，最小集是 `UI_TEMP_STOP → CTL_TEMP_STOP`、`UI_BACK_HIDE → CTL_BACK_HIDE`、`UI_AUTO_UPDATE → CTL_AUTO_DEPLOY`、`UI_DEPLOY_ENTRY → CTL_DEPLOY_ENTRY`；旧 LE 放行键已删除，无需再议。改名前必须先补 `compat.renames` 与 `profile.conf` 迁移，否则存量用户会丢配置。

### 4.2 同概念叫法

- **自动更新 / 自动部署 / 重装 / 部署**：`params.def.json` 中“自动更新”已为 0 次，“自动部署”9 次、“重装”3 次；口径基本统一，可留。
- **断联 / 断连**：定义中“断连”已为 0 次，“断联”31 次；已统一为“断联”。
- **制冷强度 / 制冷档位 / 冷值**：定义中“制冷强度”33 次、“制冷档位”3 次、“冷值”32 次。建议在 `PID_CUT` 首次出现处定义“制冷强度（0~194 档，下文简称冷值）”，其余处统一用“制冷强度”，只在表格语境用“冷值”。
- **外围开关 / 接口与外围**：`SYSFS_ENABLED` 的 label 仍是“外围开关”，建议与组名对齐为“接口与外围开关”。

### 4.3 label 与 key 含义不完全对应

- `PERF_ENABLED`（perf）→“性能总开关”：实际是“性能参数层总开关”。
- `SYSFS_ENABLED`（sysfs）→“外围开关”：实际管 sysfs 路径、缩放系数与日志路径/上限。
- `BATT_BASELINE`（batt）→“基准温度”：丢了“电池”。
- `HOT_RPM_MAP` / `HOT_DERATE`：label 未写方向/对象（映射方向、削的是制冷上限）。
- `APP_LAUNCH_TIMING` →“间隔”：实际是“拉起冷却 + 停滞重启”两件事。
- `LOG_MAX` →“日志上限”：实际是“日志大小上限”。
- `UI_TEMP_STOP` →“临时停止”：实际是“暂停温控下发”。
- `UI_DEPLOY_ENTRY` →“部署入口”：实际是“需部署时进状态页的提示开关”。

### 4.4 缩写

`KDP`、`KI`、`CH` 已分别在 `PID_KDP`、`PID_KI_RATE`、`PID_CH_THRESHOLD` 的 label/desc 中解释；`AOD` 已在 `APP_LAUNCH_SCREEN_GATE` 写“息屏显示”。旧问题已解决，可留。
