> **分析日期**: 2026-07-30  
> **结论**: **未适配** — 360 加固导致无法直接获取真实 DEX，且 App 架构与 B6X/B7X 差异极大

## 加固状态

与 B6X（无加固）和 B7X（无加固）不同，B8X 使用 **360 加固**：

- `assets/libjiagu.so` — 360 加固核心 so
- `assets/libjiagu_a64.so` — 64 位版
- `com.stub.StubApp` — Application 类（壳）
- `com.stub.stub01.StartActivity` — Launcher（壳）

因加固原因，`classes.dex` 内为壳代码，**无法通过 jadx/baksmali 直接获取真实代码**。需要 Frida 运行时 dump 或专用脱壳工具。

## 与 B6X/B7X 的关键差异

| 对比项 | B6X | B7X | B8X |
|--------|-----|-----|-----|
| App 类型 | 单散热器工具 | 超频工具 | 完整飞智生态 App |
| BLE 层 | WaspWing SDK | WaspWing SDK（混淆） | **GAIAGATTBLEService（Cyberfox）** |
| 控制 API | setRunMode(7 参数) | setRunMode(同名) | **❓ 未知** |
| 加固 | ❌ | ❌ | ✅ 360 加固 |
| 包名 | `com.flydigi.waspwing.experimental` | `com.fdg.flashplay.farsef` | `com.fdg.flashplay.farb8x` |
| 硬件上限 | 制冷 194 / 风扇 6000 | 制冷 255 / 风扇 8000 | 制冷 184? / 风扇 6000?（待确认） |

**关键差异**：B8X 的 BLE 层改为 `cyberfox.h1.services.GAIAGATTBLEService`，与 B6X/B7X 的 WaspWingManager SDK 完全不同的架构。现有的 LSPosed 钩子（针对 WaspWingManager.setRunMode、AbstractBluetoothController 等）大概率无法复用。

## 未适配原因

1. **360 加固** — 需要 Frida 运行时脱壳才能获取真实 DEX，无法本地静态分析
2. **架构差异大** — BLE 层改用 Cyberfox/GAIAGATTBLEService，与现有 LSPosed 模块的钩子体系不兼容
3. **用户决定** — 当前不进行 B8X 适配
